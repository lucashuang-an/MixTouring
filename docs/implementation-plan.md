## 1. MVP 交付范围

目标是完整跑通“发现多个有意义的走法→比较选择→对话局部调整→可信边界检查→私人保存恢复”。现有多轮对话继续作为入口，地图与状态一致性是本次补齐重点。

| 必须能力 | 当前基础 | 本次最小增量 |
|---|---|---|
| AI 多轮对话 | 已有真实模型调用与确认流程 | 稳定读取当前结构，区分修改／咨询／假设，失败保持原稿 |
| 偏好与硬约束 | 已有字段清洗与意图摘要 | 来源消息、软硬分类、总天数范围、必经城市和核实要求 |
| 多候选发现 | 已有规则、搜索、地理守门 | 将必经节点传到发现输入；候选具有稳定身份与受影响段计算 |
| 比较与选择 | 已有排序、结构键和展开入口 | 首层一个推荐及至多两个有实质差异备选；绑定当时列表序号 |
| 结构化路线状态 | 部分结构与文字并存 | 统一 TripState、版本、领域操作和原子提交 |
| 动态路线卡 | 已有草案与候选展示 | 按实体局部更新，正文与结构同版 |
| 地图联动 | 坐标与解析已有，未见地图交互实现 | 节点／示意线、卡片双向聚焦、失败降级 |
| 对话局部修改 | 已有有限字段补丁，正文整篇重写 | 插城市、改停留、假设压缩、撤销，不动未改实体 |
| 交通与来源标记 | 已有逐段线索和分级 | 跨境 verified_only 的 met／violated／unknown；不升级可执行承诺 |

不增加实时票价、酒店／活动搜索、预订、支付、精确总预算、图片或视频功能。可记录已有住宿城市与晚数；预算8000元是用户条件，不等于系统能证明总花费。

## 2. 模块开发顺序与停止条件

下列工作卡按依赖顺序交付，每卡可独立回滚。估算为单工程师专注工作日，仅用于排期，外部来源维护和不可访问等待另计；确认范围后再细排。

| 顺序 | 工作卡与预计时间 | 具体交付与复用位置 | 验收／停止条件 |
|---|---|---|---|
| 0 | 基线同步与合同确认，0.5–1日 | 重试 fetch，核对工作记录及 Issue #5；冻结 SHA；确认本次类型与四轮语义 | 远端仍不可达则明确本地基线，合并前必须重新同步；不得覆盖协作者改动 |
| 1 | 统一状态与迁移适配，2–3日 | 类型＋运行时 schema、纯 reducer、当前页面变量适配器；沿用 draft-store | 缺字段保留／null 清除；旧草案原版不丢；零候选可保存；不得先删除旧逻辑 |
| 2 | 对话领域操作与事务，2–3日 | conversation 输出受控操作；baseVersion、requestId、预览与采纳、约束冲突 | 无 key 明确失败；咨询不改状态；晚到响应拒绝；未知事实不能由 LLM 写入 |
| 3 | 路线节点与受影响段发现，2–4日 | 扩展 anywhere／route-discovery，插入伊宁、相邻段失效、稳定 ID 与比较理由 | 必经节点进入真实结构；无连接不凑卡；变化后重做分层校准，不能只跑原基线 |
| 4 | 结构化动态卡与地图，2–3日 | 提取 UI 订阅与局部渲染、地图适配器；沿用单输入、颜色和响应式样式 | 同版地图／卡片／草案、焦点与滚动保留；地图断网可继续保存；移动端无重复输入 |
| 5 | 证据策略与保存恢复，1–2日 | 复用 trip／transport-references；核实策略、方向／有效期检查、来源重新判级 | 无指定日期或证据时 unknown；恢复客户端“已核实”不得直接采信；不放宽既有 dated_verified |
| 6 | 四轮实测与审查，1–2日 | 确定性协议回归、真实模型、桌面／移动、保存恢复、真实来源抽查 | 严重条件丢失／假事实为零；全部必需门禁通过后才提交；真实发现价值独立评估 |

建议首个可运行切片为 **卡1＋卡2＋卡3的单条插入操作＋卡4的节点地图＋卡5的未知态**，先跑通北京→阿拉木图加伊宁。随后扩展多候选比较和假设停留；完整 MVP 必须完成卡6，不把骨架演示当最终交付。

不以 Layla 完整交互实测作为启动独立状态工作的前提；REA 观察若获得新证据，只作为可复核的设计输入。禁止为了模仿未经确认的接口而增加技术栈。

## 3. 四轮验收脚本

### A. 先明确首次生成的语义

第一句使用用户原话：“我想从北京去阿拉木图，10天，一个人，预算8000元，喜欢自然和本地文化，愿意坐长途巴士。”

沿当前已确认流程，AI 简短复述并请求生成确认；测试夹具加一次“确认，生成初稿”。首句直接生成的交互尚未获确认，不在本轮擅自改掉已有确认门槛。没有具体日期仍可进入探索。

断言：北京、阿拉木图、独行、十天、8000元、自然、本地文化、可坐长途巴士全部保留；十天不变成具体出发窗或十晚；“愿意巴士”是允许项，不解释为所有段必须坐巴士。候选具备节点、方式、理由、耗时／成本信息的来源或未知态。没有足够依据则少出候选并说明，不伪造第二条。

### B. 选择第二条并加入伊宁

在具有足够来源的确定性夹具中提供至少两条实质不同候选；另以真实搜索记录候选实际数量，两者结果分开报告。提交“我喜欢第二条路线，但是希望加入伊宁。”

断言：解析当时 viewId 的第二条，不受后到排序影响；伊宁为真实 stop 和用户必经条件。若原路线已含伊宁则幂等，不重复插入。若插入位置存在实质歧义先问一个问题，否则按合理位置生成探索结构。仅相邻 leg 新建，其余 ID、偏好、锚点、日期和住宿原样保留；地图同步。无法证明新连接时明确待查，不标可执行。

### C. 七天假设与采纳

提交“如果我只有7天呢？”

断言：产生七天预览，明确减少的停留／体验和交通未知项；当前十天版不被覆盖，已确认城市和兴趣保留。追加“就按七天”后才提交七天版。另测“改成七天”为直接修改。若硬约束冲突，保持原版并让用户选择放宽项；不能暗删伊宁、改交通日期或补不明耗时。

### D. 跨境必须经过核实

提交“跨境交通必须是经过核实的。”

断言：新条件成为 hard；逐个识别有向跨境段。不把同名地理结果、游记、泛查询页、货运、停运新闻或航线售期当班次。无日期时明确“本次日期班期尚不能核实”，有部分资料保留部分态；提供独立方向核查清单和可继续查的选择。不存在满足条件的方案时如实说明，原探索结构仍可保存但不能呈现为合格可执行推荐。

第四轮之前若七天仍在假设分支，核实要求应用到当前版，预览标记需重算；测试分别覆盖已采纳与未采纳两条分支。

## 4. 故障与一致性矩阵

| 场景 | 必须结果 |
|---|---|
| 模型超时、无 key、JSON 非法 | 原输入可重发，当前版本不变；不能套模板说已理解／已修改 |
| 问“为什么这条好” | 回答可引用当前版，路线结构／版本不变 |
| patch 多余字段或修改 evidenceState | schema／权限拒绝，原子回滚 |
| 相同 requestId 重发 | 返回同一结果，不插两次伊宁、不增加两个版本 |
| baseVersion 旧、两个异步结果倒序 | 拒绝旧提交，显示或重做所需部分 |
| 新段搜索失败／额度不足 | 新段 unknown，保留有效未改内容，不沿用旧段证据 |
| 地理渠道失败、国家范围或同名景点 | 提示对应问题，禁止伪确认地点或默认国家首都 |
| 跨境方向错误、日期过期、时区跨日 | 不提升证据等级，去返独立检查 |
| 预算／总时长未知 | 显示未知和待查项，不声称满足上限 |
| 地图／瓦片不可用 | 卡片、对话与私人保存继续可用 |
| 私人存储拒写、损坏、空间不足 | 不报保存成功，不覆盖坏原文，不删除旧版本 |
| plan/session 过期或服务重启 | 恢复结构并重核事实；旧 plan_id 不作为永久身份 |
| 刷新、恢复旧 vid、再对话、撤销 | 仍有效约束与节点一致，证据按当前时间判级 |

## 5. 验证与发布门禁

本轮文档交付前已实际运行：check-conversation、check-progressive、check-drafts、check-anywhere、check-pages、check-geo，全部通过。它们证明现有基线合同，不证明本次提案已经实现，也不证明真实交通可行。

开发提交前按 AGENTS 完整运行：

```powershell
node pipeline/check-pages.mjs
node pipeline/check-geo.mjs
node server/check-trip.mjs
node server/check-anywhere.mjs
node server/calibrate-routes.mjs
node server/check-drafts.mjs
node server/check-guide.mjs
node server/check-journey.mjs
node server/check-progressive.mjs
node server/check-inspirations.mjs
node server/check-sights.mjs
node server/check-conversation.mjs
node server/check-travel-sources.mjs
```

启动隔离端口的无 key 服务后运行 `node server/verify.mjs`；真实搜索与模型使用另一实例／环境执行 `replay-discovery`、四轮对话回放，并保存脱敏逐段证据与未满足项。不得把无 key 全探索断言与真实搜索 source_lead 的差别当成可以忽略的普通测试失败。

新增测试重点是会丢约束、串版本、污染证据或错误保存的真实风险；不为颜色微调写镜像测试。真实模型回放不能由固定桩代替。浏览器验证覆盖桌面与390px，至少完成讨论→确认→比较→选择→加伊宁→七天预览／采纳→核实要求→保存→恢复→继续修改。测试后恢复视口。

**两条独立门禁**：

- 工程门禁：合同一致、版本与取消正确、旧数据不丢、地图与卡片同版、全部必需回归通过。
- 产品与事实门禁：候选有实质差异、理由有价值、真实来源可复核、缺证据诚实降级；真实用户能完成选择。不能用工程绿灯替代路线发现价值验收或指定日期可执行验收。

真实前瞻样本应使用用户新的未来日期；2026国庆案例仅作历史回归，不擅自延用为当前出行日期。

## 6. 确认后才进入开发

建议确认：沿用现有栈和生成确认流程；“如果七天”先预览；成本／时长未知允许保留；跨境核实要求未满足不凑可执行路线；本机私人保存继续作为 MVP 持久层。确认后先完成卡0，重新查工作记录与 Issue #5，按每卡更新记录、验收后递进。本轮不提交、不推送、不创建 PR，也不发布新的产品评审评论。
